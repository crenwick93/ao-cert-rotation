# Requirements

## Platform

| Component | Version | Notes |
|---|---|---|
| Red Hat AAP | 2.5+ | Controller + EDA + Gateway |
| Automation Orchestrator | 2026.8+ | AO workflows, approval gates, agentic nodes |
| ServiceNow | Washington DC+ | PDI or production instance |
| Terraform | 1.5+ | For EC2 provisioning (optional) |
| AWS | Any | For demo host provisioning (optional) |
| HashiCorp Vault | 1.15+ | Runs as container on demo VM (auto-provisioned) |
| Splunk Enterprise | 9.x+ | Runs as container on demo VM (auto-provisioned) |
| LiteLLM | Latest | AI proxy for AO agentic nodes (optional — can use direct model access) |

## Ansible Collections

Install via:

```bash
ansible-galaxy collection install -r ansible_deployment/cac/requirements.yml
```

| Collection | Purpose |
|---|---|
| `infra.aap_configuration` | Configuration as Code for AAP |
| `ansible.controller` | Controller API interactions |
| `servicenow.itsm` | ServiceNow incident and change request management |
| `community.crypto` | OpenSSL certificate operations (EE only) |
| `containers.podman` | Podman container management (EE only) |
| `ansible.posix` | Firewall and cron management (EE only) |

## Execution Environment

The EE includes all collections needed for cert renewal playbooks:

- Image: Build from `dependencies/ee/execution-environment.yml` or provide your own
- Build script: `./dependencies/build-images.sh`

## EDA Decision Environment

The EDA rulebook uses the `servicenow.itsm.records` source plugin for CR approval bridging:

- Image: Build from `dependencies/de/decision-environment.yml` or provide your own
- Build script: `./dependencies/build-images.sh`

## Credentials Required

| Credential | Purpose | Where to Get |
|---|---|---|
| AAP OAuth Token | CaC deployment + EDA controller auth | AAP → Users → Tokens |
| ServiceNow credentials | Incident/CR management + EDA polling | ServiceNow instance admin |
| AO Webhook credentials | EDA-to-AO bridge | AO → Publish workflow → EDA trigger |
| AO Service Account | Approval bridge | AO → Settings → Service Accounts |
| GitHub PAT | Commit files + raise PRs from workflows | GitHub → Developer settings → PATs |
| Vault Token | Certificate issuance from PKI engine | Auto-generated (dev mode: `demo-root-token`) |
| AWS credentials | EC2 provisioning (optional) | AWS IAM |
| SSH key | Demo host access | Generated by Terraform |
| Anthropic API Key | LiteLLM AI proxy | Anthropic console |

## DNS / Networking

- The `CERT_DOMAIN` (e.g. `certdemo.demoredhat.com`) must resolve to the demo VM's IP
- Option A: Create a DNS record (Route 53 or your DNS provider)
- Option B: Add to `/etc/hosts` on your local machine for demo purposes
- The demo VM needs outbound internet access for package installation
- AO must be able to reach the demo VM on ports 443, 8443
- Splunk must be able to reach AO's webhook endpoint
